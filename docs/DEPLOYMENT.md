# 배포 안내

현재 GitHub Actions 자동 검사는 미설정입니다. 연결된 GitHub OAuth 앱에 workflow 쓰기 권한이 없어 활성 workflow를 업로드하지 않았습니다. 기본 검사는 로컬에서 `node scripts/check-site.mjs`로 실행할 수 있습니다. [CI 예제](ci/source-checks.example.yml)는 비활성 문서이며, 추후 저장소 관리자가 검토하여 `.github/workflows/check.yml`에 등록하면 소스 검사만 수행합니다. 운영 배포, DB 생성·이관, 계정 연결, 퀘스트 자동화는 포함하지 않습니다.

1. GitHub 변경을 검토하고 검사·화면 확인 결과를 확인합니다.
2. 담당자는 현재 Sites 버전과 배포 소스를 다시 조회합니다. Sites에서 따로 수정된 내용과 파일별로 대조하며 기존 변경을 보존합니다.
3. 승인된 GitHub 변경만 Sites의 기존 소스 관리 흐름에 반영합니다. 기존 사이트 ID·접근 범위·저장소 바인딩을 보존합니다.
4. 필요한 빌드·미리보기·사용자 권한 검증을 수행하고 기존 Sites 저장·배포 도구로 게시합니다.
5. 배포 버전과 GitHub commit의 대응, 실제 URL, 검증과 남은 한계를 손잡고에 보고합니다.

`.openai/hosting.example.json`은 정적 디자인의 구성 예시입니다. 실제 배포를 자동 연결하거나 권한을 부여하지 않습니다. Fork의 예시를 기존 운영 사이트에 그대로 적용하지 마세요. 서버·DB 도입 시에는 정적 구성과 다른 검토가 필요합니다.

GitHub 저장소의 권한·브랜치 보호·Sites 배포 권한은 각각 별도로 관리합니다. 리뷰 절차는 참여 규칙이며, 현재 GitHub의 강제 브랜치 보호 설정을 의미하지 않습니다.
